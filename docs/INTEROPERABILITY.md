# Interoperability validation

## Method

Each supported algorithm must be validated per operation and per key version. Local round trips are recorded separately from independent-implementation results. GnuPG tests use an isolated temporary `GNUPGHOME` and disposable keys; they never read or modify the user's normal GnuPG keyring or Git-signing configuration. The isolated agent configuration disables `scdaemon` so software-key tests cannot access a physical card. Verification time is sampled after receiving each peer-generated signature or message, rather than before running the peer operation.

The test matrix covers, where applicable:

- Generation, public/private import, public export, and policy-controlled private export.
- Detached, attached, and cleartext signatures and verification.
- Encryption, decryption, multiple recipients, and binary/armored messages.
- Sign-then-encrypt and decrypt-then-verify.
- RSA-2048, RSA-3072, RSA-4096, modern and legacy Curve25519, NIST P-256/P-384/P-521, and Ed448/X448.
- v4 and v6 encodings where allowed by the selected compatibility policy.
- Tampered messages, invalid signatures, unknown signers, revocation, expiration, and Key Flags.

Brainpool operations remain unavailable unless cryptographic implementation and independent interoperability tests pass. Historical algorithms are limited by security policy rather than enabled solely because a parser recognizes them.

## Legacy algorithm policy evidence

On 2026-10-29, real rPGP-generated RSA signatures exercised MD5 and SHA-1 in detached, attached, cleartext, and sign-then-encrypt messages. The tests independently checked the underlying signatures before evaluating application policy. MD5 was cryptographically valid but rejected without releasing attached, cleartext, or decrypted plaintext; SHA-1 remained valid with a structured weak-hash warning. Custom SHA-1 rejection was also exercised. Modern v4 and v6 messages produced no legacy warning. Results are in `build/legacy-policy-core-20261029.log`.

Real SEIPDv1 messages using IDEA, TripleDES, CAST5, and Blowfish verified the default allow-with-warning behavior and per-algorithm rejection. Rejected ciphers did not write plaintext staging. A real FFI MD5/SHA-1 signed-and-encrypted message test verified memory output, stable algorithm identifiers, and file-staging cleanup: MD5 produced no plaintext or destination file, while SHA-1 produced the expected content with its warning. Results are in `build/legacy-policy-ffi-files-20261029.log`.

These are local policy and format tests, not claims of independent GnuPG support for weak algorithms. The independent suite continues to use modern algorithms for new signatures and encryption; its current results remain separate below.

`docs/algorithm-capabilities.json` is generated from the policy crate. Implementation and unit-test evidence is recorded for lifecycle and message operations separately; independent evidence is recorded only for operations executed by the GnuPG suite above. An operation is fully supported only when implementation, unit tests, and independent interoperability all pass, with physical-device evidence additionally required for hardware backends.

Secure Enclave and physical card rows require physical-device evidence. Simulator, mock-card, and software tests must not fill those rows.

## Release-validation gate

On 2026-10-28, `bash scripts/test.sh` passed Rust formatting, Clippy, and all 158 workspace tests, with two explicit interoperability ignores, before returning failure at the dependency audit. The online RustSec fetch failed with a network I/O error, so this invocation does not establish current online advisory coverage. It scanned all 221 locked packages, reported zero license-policy failures, and retained the missing authoritative license texts for `cx448 0.1.1` and `hex-slice 0.1.4`. The command did not reach the later interoperability, Swift package, or native application stages. `build/se-biometric-standard-complete-20261028.log` retains the completed invocation; an earlier tool-timeout interruption was not counted as a completed validation.

A separate supported audit invocation selected the previously cloned official RustSec snapshot at `a78282a1414d6c28cc228c4eae3570451affb0dc` with `--no-fetch`. It loaded 1,378 advisories, scanned all 221 locked packages, and returned failure for `RUSTSEC-2026-0387` and the same two missing license texts. `build/se-biometric-dependency-audit-snapshot-20261028.log` records this supplemental result. It does not establish coverage of advisories added after that snapshot, suppress the known vulnerability, or represent a successful online audit.

The interoperability, Swift package, and native application suites were therefore also executed separately and are recorded above. Their individual results are not a claim that the complete release-validation command succeeds.

Both `bash scripts/build-ios.sh Debug` and `bash scripts/build-ios.sh Release` passed as simulator builds using the passwordless Secure Enclave generation API, biometric ACL selection, generated bindings, and XCFramework. The latest Release result on 2026-10-29 is `build/legacy-policy-release-20261029.log`; the Debug application build is included in `build/legacy-policy-native-20261029.log`. The compiled application contains the Face ID usage description and the new English and Simplified Chinese interface strings. This verifies compilation and packaging, not an App Store signature, physical-device deployment, biometric authorization, or release approval.
